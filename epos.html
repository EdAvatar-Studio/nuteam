The EPOS Story

A Dense Syntax for Cutting AI Token Cost

Public spec & extension — coming soon

Every AI conversation costs tokens — and tokens cost money, time, and access. For people working with a fixed budget or a limited free-tier quota, every unnecessary word in a prompt is a real cost. Long, natural-language prompts are easy to write but expensive to repeat.

EPOS (Efficient Prompt Operating Syntax) is a compact command syntax built to carry the same intent in a fraction of the tokens, while staying readable enough for both humans and AI models to parse without a decoder in between.

What EPOS Looks Like

Here is a real EPOS v1.5 command, used to brief an AI on a visual scene:

[#GENERAL @BRIEF >> VisualAnalysis[Scene:FamilyPortrait] >> Entities[Family:Father+Mother+Daughter, Mech:GiantRedRetroRobot] >> Setting[Landscape:AridDesert] >> Theme[Style:RetroFuturism, Mood:SurrealDystopia] >> Apply[!No_Greetings>>!Max_Density] #GENERAL]

Written out in plain English, this would normally read something like:

"I want you to analyze/generate a visual scene. It's a family portrait featuring a father, mother, and daughter, alongside a giant red retro-styled robot. The setting is an arid desert landscape. The visual style should be retro-futurism, with a surreal, dystopian mood. Please don't greet me, and keep your response as dense and information-packed as possible."

The EPOS version carries every one of those fields — entities, setting, style, mood, and behavioral flags — in roughly a fifth of the words.

Reading the syntax

  • [#TAG ... #TAG] — a named block, opened and closed
  • @BRIEF — the command type (what kind of instruction this is)
  • >> — separates sequential fields/steps
  • Field[Key:Value] — a labeled field with structured values
  • !Flag — a behavioral instruction (e.g. !No_Greetings, !Max_Density)

Cross-Platform Testing

EPOS v1.5 has been tested directly — no decoding step, no explanation needed — against a wide range of AI tools: ChatGPT, Copilot, Gemini (2.5 and 3.5), DeepSeek, Grok (in image-generation mode), Dola AI, and Claude. All of them correctly parsed the dense syntax and extracted the intended fields, which is notable — the previous syntax generation (v2.5) failed to parse in several of these same tools.

What Works Reliably, and What Doesn't

Concrete, visible fields — entities, setting, style — are followed reliably by every tool tested. If you specify a giant red robot and a desert, you get a giant red robot in a desert.

Abstract, mood-based fields are inconsistently interpreted. Mood:SurrealDystopia was ignored entirely by one image generator (which produced a cheerful 1950s postcard scene instead), while another captured it strongly.

Routing matters. Sending EPOS's code-like syntax to an agent/coding-oriented mode instead of an image-generation mode can cause an AI to misclassify the whole request as a programming task. In one test, this produced an unexpected but genuinely interesting result — a full fictional interactive webpage, built as if EPOS were a spec document — arguably capturing the intended mood even better than a static image would have.

Why This Matters Beyond Convenience

The point of EPOS isn't to squeeze the maximum percentage out of every prompt. On free-form or creative writing, the savings are close to zero. The real value shows up on structured, repeatable tasks — the same kind of brief, sent over and over, where most of the wording is boilerplate a dense syntax can carry instead.

For someone on a fixed AI budget — a free-tier quota, a small monthly allowance, a shared account — that difference adds up. It's not about chasing a discount. It's about making a fixed amount of AI access go further.
